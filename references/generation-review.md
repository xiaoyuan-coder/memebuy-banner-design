# 生图、验收与定点返修

适用于首轮生图、用户反馈修正、App/Web 导出与交付。目标是让用户尽快看到可判断的三张成图，同时把可验证的技术错误留在交付前解决。

## 构建生成输入

每个方向把下列内容组合成一份短而明确的输入：

1. **准确业务：**活动对象、指定主标题与辅助文字、必须表达的商品和权益；价格/日期只用已确认数值。
2. **参考图与视觉指纹：**提供原始参考图，写 3–5 个可执行的画风特征，并要求标题、主体、背景共用这套画法。
3. **单一创意：**一句话说明画面如何表达卖点，以及主体和标题如何互相解释。
4. **Banner 结构：**确定一种标题位置；标题是第一焦点，主体是第二焦点；连续满幅背景延伸到四边，上下避让区安排非关键画面，完整关键内容留在核心区。
5. **色彩与排除项：**指定 C 编号及 HEX，说明与参考配色的关系；排除不属于业务的道具、冗余文字、页面 UI 和画风不一致的素材。

坐标可以写进输入，但生成模型对精确几何的遵守不稳定。通过空间语义提高命中率，再用生成结果验收。缺少原始参考图时，先寻找用户已提供的原图；不要把上一轮生成图当成新的风格源。

## 首轮与时间控制

用户请求实验时，直接生成三个可比较的 App 方向；工具允许时并行。不要先提交一套长篇文字方案让用户评审。完成首轮后先做一次集中检查，并交付可判断的图。若失败原因已明确，只返修受影响的方向；向用户说明核心问题和改动点，避免无目标的多轮生图。

生成式返修从**原始业务需求＋原始参考图＋累计修正要求**重新构建输入。裁切、尺寸适配和可编辑文字排版属于非生成式处理，可用于已有图；不能靠拉伸、上下补边或整体缩小掩盖主体越界和失衡。

## 交付前检查

按下面次序检查，先处理会让整图失效的问题：

| 关口 | 看什么 | 未通过时 |
| --- | --- | --- |
| 业务准确 | 指定中文、数字、权益、商品、日期与跳转表述 | 修正文案或重生；不得用伪文字交付 |
| 一眼可读 | 375px 宽下标题先读到，主体能解释主张，辅助字可辨 | 压缩内容、调整布局或文字排版 |
| 画风同源 | 标题、主体、背景的线条、形状、材质和颜色逻辑一致 | 找出异质元素，按原始参考重新画该方向 |
| 创意与密度 | 一个主张、一个主要关系；装饰有叙事或导视作用 | 删减竞争焦点，增强视觉隐喻 |
| 安全与满幅 | 图像铺满四边；标题含描边阴影、面部与商品细节在核心区 | 从原始输入调整构图；检查 App 和 Web |
| 主题色 | 选定 C 色号在主要视觉中可见，整体配色协调 | 调整面积与对比，勿让主题色吞没参考气质 |
| 文件技术 | App/Web 尺寸、PNG 不透明、Web 像素与 App 指定裁切一致 | 用本 Skill 裁切脚本重导出 |

如需修中文错字，优先尝试重新生成准确字形；也可使用与画风匹配的可编辑排版覆盖，随后重新检查构图、清晰度和安全区。生成图的“看着差不多”不足以证明优惠数字正确。

## 页面验收与汇报

Web 从 App `y=144–864` 精确裁切。实际手机端用 375×250、100% 缩放检查；再放进 V2.1 首页检查底部渐变、双入口叠加、滚动与收起状态。缺少真实页面时交付图仍可用于审美评估，但明确标注“真实首页待验收”。

每个方向汇报选定 C 色号与 HEX、标题布局、实际显示的文案、设计创意和未完成的验收项。用户给审美反馈时，记录可观察的问题及其发生环节，优先修复成图；经过成图验证后再改 Skill，避免把一次主观判断写成永久硬规则。
