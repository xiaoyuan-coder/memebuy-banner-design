# 执行流程：App Banner 生图与评估

本文件负责把[参考图层](reference-analysis.md)和 Banner 层的[创意判断](banner-design.md)、[制作规范](production-rules.md)落实到成图、评估与修订。当前只交付静态 App 素材，并按用户要求保留**每张完整 Banner 一次生图**。探索阶段的完成条件是**按约定数量产出可比较的方向，每个方向各有一张图，问题已标注，用户可以判断方向**；画面未达标本身不触发下一轮生图。

## 单次完整生图预检

先确认[制作规范](production-rules.md)中的硬边界，再按[文案准入、批次配比与构图决策](banner-design.md)完成以下准备，最后写生成提示词：

1. 确定实际入画文案，记录哪些事实由图像或落地页承接；辅助说明按必要性判断。
2. 提炼参考的 2–3 个视觉特征及空间组织方法，说明怎样落实到标题、业务主体和背景，并列出需替换的识别性元素。
3. 按批次配比分配常规与探索方向，在产品允许的标题位置和核心区内描述图文关系，再画粗占位或记录尺度、层次与坐标目标。每个元素能解释业务或支持该关系。
4. 按[批次检查](banner-design.md#方向之间的差异)核对配比、阅读密度与逐稿边界。常规稿可复用左右骨架，探索稿边界不足时简化或回退；单图及统一版式任务按对应分支处理。

完成条件：入画文字有保留依据，主要元素有用途，完整关键内容及内部缓冲能落入产品边界，常规／探索分配与主要差异已记录。探索的复杂度或新颖程度不降低这些要求。未通过时先简化方案，不提交生成。

把完整标题及描边阴影放在[制作规范](production-rules.md#标题布局与可读性)所选范围内，人物面部、商品关键细节和行动文字放入核心区；顶部和底部由同风格的低信息场景延展。空间不足时先删减非必要文字与元素，再调整尺度和图文关系。标题的视觉重量在 375px 宽检查；安全区内的安排服从本稿构图。

只调用一次工具生成完整图。上一轮尝试的透明主体素材不纳入本流程；当前不通过多次生图、外部排字或图层合成补救构图。生成后如实标记错误与严格安全区结果，交用户判断下一次版本的方向。

## 方向预检

生图前的简短记录包含实际文案与点击去向、主要画面关系、所选标题布局，以及文字、按钮、面部、商品关键细节的目标区域。标出标题重点字及完整字形、描边和阴影，把印花计入商品关键细节，并与[制作规范](production-rules.md)的核心区保留内部缓冲。图文可共享空间或前后叠合，文字完整性、面部与商品关键细节的识别仍须成立。省略说明的稿件直接重分配空间。占位是生成目标，成图仍需实测。

同时写一条“视觉系统映射”：参考中的主体画法、场景结构、材质、互动关系和图文嵌合，分别将在新 Banner 的哪些部分重现。若只能写出颜色和标题字形，先补足画面设计。对有角色或独特道具的参考，预先说明原创替身如何承接画面关系，以及哪些身份识别点会更换。

若含商品印花，记录其来源：已确认图案、业务指定的示意要求，或经用户允许的探索示意。探索示意须与业务主题有关，限制在一个清楚的原创图形或紧凑组合内，控制印制位置与尺度；同款团服使用同一图案，并在评估中注明“印花仅为示意，商品外观待确认”。没有可用图案且未允许示意时，使用无印花商品或避开印花展示。真实商品外观、指定印花与文字以业务素材为准。来源不明的现成角色、标志和随机文字不进入印花；若整图生图不能准确呈现指定图案，保留探索稿标记，定稿前须重新核对，不能把近似印花当作指定商品外观交付。

## 首轮生成

按用户指定数量生成，未指定时默认三个方向，每个方向调用生图一次，直接生成完整图。准备记录可在内部完成，直接展示 App 图，不以长篇文字方案作为审批关口。每个方向的输入包含：

1. 已核实的业务事实及本稿实际入画文案；主标题和活动按钮逐字列出，通过必要性判断的说明才列入。已省略信息的去向保存在工作记录中。
2. 原始画风参考图与 2–3 个高辨识的视觉特征，以及须替换的识别性元素；标题、主体、场景共享这些造型、材质或空间方法。参考的常见构图可重组，独特主体与具体画面需重新设计。
3. 一句话创意、主视觉焦点由哪些元素承担，以及标题、主体与活动按钮的空间关系；用尺度、层次或动势落实本稿的结构选择。
4. 一种标题布局及预检得到的关键内容目标区域：主标题先被读到，重点数字／关键词在标题内部有适度造型差异，活动按钮清楚可见，背景和材质延伸至四边。
5. 选定 C 编号与 HEX 在画面中的作用；需要真人实景时说明摄影条件，需要商品印花时说明图案来源与位置；排除冗余文字、未经证实的业务表达与页面 UI。

共用提示词只包含确实共享的业务事实、产品约束与文字要求；标题断行、元素数量、主体类型、坐标、按钮形状和材质由各稿方案决定。统一版式或控制变量任务可按要求共享相应项。逐稿核对最终提示词与已通过的构图记录一致，避免共用段落重新覆盖各稿的空间关系或补回已删除文案。

提示词描述阅读顺序、主视觉焦点、图文关系与边缘延展；有可靠构图参考时可附带。坐标、字号和精确色号仍作为成图后的测量条件，输入中写了数值不等于输出合格。若包含真人实景，写清可信的姿态、材质、光照与空间关系；实际质量以成图检查为准。

## 区域功能提示词与内部缓冲

将预检选定的构图写进提示词时，说明上方与下方的背景延展、中段实际关键内容及它们的关系。关键内容要比[制作规范](production-rules.md)的验收边界更向内收，给生成偏差留缓冲；完整标题及描边阴影、行动线索、面部、手、商品细节和业务关系符号都计入占位，辅助说明只在入画时计入。背景依当前画风延展为纸纹、天空、色块或场景，不做独立空白条。

依据本稿标题长度、主体规模和关系选择内部余量。当前画布为1440×1000，顶部避让占25.6%、核心纵向为25.6%–80%；这些比例用于理解区域，具体标题仍按所选标题框安排。历史1440×960稿的百分比不能直接套用。

生成工具曾返回1536×1024，提示词中的目标尺寸不保证实际输出。先核对文件尺寸与比例：36:25可等比缩放；若返回3:2，可等比导出1440×960后向下扩40px画布，仅非生成式延续底部背景与阴影，保持原有内容位置并检查接缝。其他比例先判断等比适配是否损失关键内容；无法安全适配时记录尺寸未达标。避免非等比拉伸、整体缩小塞背景或自动追加扩图调用。适配后按最终1440×1000坐标重新验收。旧稿扩高同样要复核新顶部范围。

遇到反复越界、需要回查历史缓冲实验时，读取[五个业务需求的三轮安全区测试](experiment-findings.md#五个业务需求的三轮安全区测试)；这些是旧尺寸实验，不作为当前布局保证。

## 首轮评估与停点

逐张检查下表，并把具体失败项连同原图交给用户。**首轮完成后停止生成、扩图、覆盖文字与修图，等待用户判断方向和提出修改。**失败项只作为判断信息；如果没有一个方向值得保留，用户可以决定重新探索。此前累积的修订意见不能替代本轮方向判断。

| 关口 | 检查内容 | 首轮表达方式 |
| --- | --- | --- |
| 业务准确 | 指定中文、数字、权益、商品、日期与去向 | 逐项指出错字、伪文字或未经确认的表达 |
| 一眼可读 | 375px 宽下标题先被看到，主体解释主张，按钮及实际入画的说明可辨 | 标出文字被挤成角标、辅助字太小、按钮缺失、拥挤或焦点冲突的区域；说明缺省本身不构成遗漏 |
| 文案取舍与字形重点 | 业务事实准确，长句已压缩或转到落地页；标题中的数字／关键词有适度设计且清楚可读 | 指出原需求逐字上图、小字无法读、重点字被抹平，或设计干扰识别 |
| 视觉方法与参考边界 | 忽略颜色和文字后，主体造型、场景结构、互动、材质仍能体现参考的画面语言；独特角色、标志及识别性组合已重新设计或替换 | 分别指出“只借配色字体”的表层相似或“具体主体照搬”的过近相似 |
| 创意与密度 | 一个主张、一个主要画面关系；重复权益牌及无解释作用的装饰已取舍 | 指出争夺注意力的元素及可删项 |
| 主体层级 | 主视觉焦点清楚，商品、人物、图形或场景组合内部有主次 | 标出竞争焦点、无作用道具及挤占文案或安全区的元素 |
| 批次构图（多方向） | 常规为主、少量探索，均符合通用规范；常规稿有可比较的视觉变化，探索关系清楚克制 | 标出探索过多、内容变乱、关键区域越界或预定变化丢失；常规骨架复用本身不判失败，首轮不自动追加生图 |
| 真人实景质感（如使用） | 手指、肢体、肤质、场景透视、接触阴影、噪点、边缘与光照自然可信 | 标出明显生成感与局部缺陷，不自动返修 |
| 商品印花（如使用） | 图案来源、内容、位置、尺度及同款一致性符合预检与业务素材 | 标出随机图案、文字、标志或不一致之处 |
| 安全与满幅 | 背景铺满；完整文字及描边阴影、面部、商品关键细节位于核心区 | 按实际图片尺寸叠加安全区，记录越界的对象与边界 |
| 主题色 | 选定 C 色号可见，且画面协调 | 记录实际观感与编号 |
| 文件技术 | App 1440×1000、不透明 PNG；底部40px为连续背景与阴影 | 记录实际尺寸、格式、透明边或适配接缝；技术通过不代表内容边界通过 |

## 用户选定方向后的修订

用户选定方向并提出反馈后，针对选中方向修订。先把反馈拆成**保留项、改动项、待验项**：保留项写到可观察的造型与构图层面，例如人物轮廓、线条粗细、面部简化程度、填色面积、道具数量与主体比例；改动项写清文案、按钮或位置；待验项保留安全区等尚未通过的检查。

把保留项和改动项合并为一份完整提示词，**从原始需求、原始参考与已确认业务素材重新生成**。旧成图用于对照并提炼已认可的局部画法，默认不作为下一轮生成式重绘底图；这与源规范一致，也回应连续重绘带来的模糊和噪点问题。例如只改左侧文案时，将右侧已认可人物的线条、表情、填色和配饰复杂度写成可观察的保留条件；用户角色身份素材与外部画风参考仍分开标注。每张完整 Banner 每轮只调用一次生图，成图后逐项核对保留项、改动项及新边界，再交用户判断。

尺寸变化与位置修改分开处理：底部扩40px不解决顶部避让增大或标题过宽，须把具体越界对象纳入下一轮构图。单纯裁切、等比尺寸适配等非生成式处理可以操作已有图，仍需检查字形、商品与背景衔接。

## 安全区控制：单次生图与验收

每张图生成前用[制作规范](production-rules.md)确定标题布局和关键内容可用范围，给完整文字、面部、商品关键细节和行动线索留内部缓冲。提示词说明画面高度中部的内容关系，顶部与底部承载同风格的低信息背景延展；不要把它写成顶部长条留白或底部长条留白。明确排除顶部大标题、底部信息栏和边缘小字。当前每张只调用一次完整生图，不生成分层素材或做受控合成。

成图后按实际尺寸检查边界，记录具体越界对象。若单次生图未满足严格安全区，保持探索稿状态并交用户判断；只有下一次得到用户对该方向的反馈，才可再做一版完整生成。任何不满足边界的稿件不得标作定稿达标。历史受控合成与扩图想法保留在实验记录中，不作为当前用户要求的执行步骤。

## 页面检查与汇报

成图先完成下节的文件与边界检查，再在375px宽、约260.42px高、100%页面缩放的完整等比显示下检查标题、按钮及实际入画的说明。能接入V2.2首页时，另查遮罩、双入口、轮播指示条、展开、滚动、吸顶和回到顶部；确认页面已取消额外10px延伸。没有真实环境时标注“真实首页待验收”。每方向汇报主题色编号及HEX、标题布局、实际文案、创意与具体未达标项。

用户反馈先记录在 [实验反馈](experiment-findings.md)，并按反馈处理成图。候选方法保留适用条件与待验证状态；经过不同任务的实际成图验证后，再升级为稳定规则。

## 检查工具与边界记录

安装Pillow后，对最终App图运行Skill目录下的工具，选择本稿标题布局（`left`／`right`／`center`／`lower`）：

```bash
python3 scripts/check_banner.py /absolute/path/banner.png --layout left --out /absolute/path/checks
```

工具只读取原图，输出独立安全区叠层、375px初筛图和JSON报告；不会改原图或把辅助线写入交付素材。它检查PNG、1440×1000、不透明像素，标注核心区、标题框、800／806／860／960边界及页面遮罩起点856.32。尺寸不符时只报告技术失败，不套用错误叠层。

查看叠层后，逐项记录主标题、CTA、面部、商品关键细节的实际外框，含描边、阴影、毛绒外沿等。OCR框只定位字形，需人工补足可见外沿。记录格式可通过`--regions /absolute/path/regions.json`传入：

```json
[{"name":"主标题含投影","kind":"title","box":[120,320,700,610]},
 {"name":"活动按钮","kind":"cta","box":[180,660,600,770]}]
```

`kind`支持`title`、`cta`、`face`、`product`、`key`，`box`为最终原图的`[左,上,右,下]`，右下界不包含；标题查所选标题框，其他关键内容查核心区。工具只判断已提供外框是否越界，无法自动识别对象、证明标注完整、读取文字或验证精确字号和主题色。未标注时内容边界状态为待人工测量；即使已提供框全部通过，仍要人工核对遗漏、阅读、参考边界及真实首页。记录具体对象、外框、超出哪条边以及未测项，分别汇报文件、内容与页面状态。
