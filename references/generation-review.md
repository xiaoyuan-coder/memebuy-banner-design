# 执行流程：App Banner 生图与评估

本文件负责把[参考图层](reference-analysis.md)和 Banner 层的[创意判断](banner-design.md)、[制作规范](production-rules.md)落实到成图、评估与修订。当前只交付静态 App 素材，并按用户要求保留**每张完整 Banner 一次生图**。探索阶段的完成条件是**按约定数量产出可比较的方向，每个方向各有一张图，问题已标注，用户可以判断方向**；画面未达标本身不触发下一轮生图。

## 单次完整生图预检

先做画面文案清单和文字与主体的粗占位图，再写提示词。画面设置三个主要阅读层级：**主标题／权益 → 一个解释活动的主体关系 → 活动按钮**；确有必要的短条件附属于主标题。先把业务长句编辑成手机上读得清的文案，记下哪些事实转入落地页；主标题、短说明和按钮文案均明确写入生成输入。参考视觉选 2–3 个高辨识特征，并说明它们在标题、主体和背景中的体现；删除会构成第二主角的装饰与道具。列出允许出现的文字，同时指定标题内重点字的视觉处理；避免额外口号、伪文字和重复权益牌。标题内颜色或尺度变化不算新增文案。

给标题一块足够大的中段占位，避免 rc1 的小角标；把完整字形、描边和阴影限制在[制作规范](production-rules.md#标题布局与可读性)所选布局内，标题的视觉中心放在画面高度中部。人物面部、商品关键细节和行动文字一起放入核心区，顶部和底部由同风格的低信息场景自然延展。避免 rc2 的顶置海报标题、底部密集小物和把商品或 CTA 推到边缘。若文字与主体合计放不进中段，先简化主体关系和非必要文字，再提交生成。

只调用一次工具生成完整图。上一轮尝试的透明主体素材不纳入本流程；当前不通过多次生图、外部排字或图层合成补救构图。生成后如实标记错误与严格安全区结果，交用户判断下一次版本的方向。

## 方向预检

生图前为每个方向写一份简短占位说明：一句主张、必要短说明、活动按钮及其点击去向、一个主要主体或紧凑场景、所选标题布局，以及文字、按钮、面部、商品关键细节各自的目标区域。标出被强调的标题字及其完整字形、描边和阴影；把印花计入商品关键细节。目标区域应与[制作规范](production-rules.md)的核心区保持内部缓冲，并能彼此错开；内容拥挤时先按[创意与构图](banner-design.md)精简或改写可选说明，再调整主体。**单独预检文字组的面积与视觉重量**：左右文字优先时可从约 50%–60% 横向布局空间起稿，避免人物或商品把标题挤成小角标。此预检是构图决策，成图仍需实测。

同时写一条“视觉系统映射”：参考中的主体画法、场景结构、材质、互动关系和图文嵌合，分别将在新 Banner 的哪些部分重现。若只能写出颜色和标题字形，先补足画面设计。对有角色或独特道具的参考，预先说明原创替身如何承接画面关系，以及哪些身份识别点会更换。

若含商品印花，记录其来源：已确认图案、业务指定的示意要求，或经用户允许的探索示意。探索示意须与业务主题有关，限制在一个清楚的原创图形或紧凑组合内，控制印制位置与尺度；同款团服使用同一图案，并在评估中注明“印花仅为示意，商品外观待确认”。没有可用图案且未允许示意时，使用无印花商品或避开印花展示。真实商品外观、指定印花与文字以业务素材为准。来源不明的现成角色、标志和随机文字不进入印花；若整图生图不能准确呈现指定图案，保留探索稿标记，定稿前须重新核对，不能把近似印花当作指定商品外观交付。

## 首轮生成

默认提出三个有实质差异的方向，每个方向调用生图一次；用户指定数量时按其要求。每次调用直接生成整张图；用户要求当前五项对照测试时，每项一张、各一次。直接展示 App 图，不以长篇文字方案作为审批关口。每个方向的输入包含：

1. 已核实的业务事实、锁定文案与本稿编辑后的画面文案；列出主标题、必要短说明、活动按钮，注明由图像表达或移至落地页的事实。
2. 原始画风参考图与 2–3 个高辨识的视觉特征，以及须替换的识别性元素；标题、主体、场景共享这些造型、材质或空间方法。参考的常见构图可重组，独特主体与具体画面需重新设计。
3. 一句话创意，以及标题与一个主体加一个必要伴随物如何互相解释。多人确有业务需要时组织为一个紧凑动作，避免多个同等尺度的大主体并排。
4. 一种标题布局及预检得到的关键内容目标区域：主标题先被读到，重点数字／关键词在标题内部有适度造型差异，活动按钮清楚可见，背景和材质延伸至四边。
5. 选定 C 编号与 HEX 在画面中的作用；需要真人实景时说明摄影条件，需要商品印花时说明图案来源与位置；排除冗余文字、未经证实的业务表达与页面 UI。

提示词要描述阅读顺序、单一主视觉锚点、视觉核心、边缘延展和非关键边缘；有可靠构图参考时可附带。坐标、字号和精确色号仍作为成图后的测量条件。已观察到区域功能写清后可一次得到安全区较好的成图，也观察到后续逐像素返修未必更好；输入中写了数值不等于输出合格。若方案包含生成真人实景，还要明确可信的姿态、材质、光照与空间关系；实际质量以成图检查为准。

## 区域功能提示词与内部缓冲

按当前画风和信息量组织首轮提示词：先规定**上方和下方的背景功能**，再逐一列出**必须完整留在中段的关键内容**，最后为标题和一个主要主体安排能装进中段的关系。关键内容要比[制作规范](production-rules.md)的验收边界更向内收，给生成偏差留缓冲；标题连同描边阴影、辅助文字、行动线索、面部、手、商品细节和业务关系符号都计入占位。空间不够时先压缩文案或简化主体，再决定各区域的目标比例。

下面是一组白底插画实验使用的功能描述，可按当前画风改写。它曾使“一起团 更便宜”的三张图较好地守住核心区；另一组“低至5.7折”虽视觉聚合，红色标题仍越过规范：

> 画面铺满 3:2 App 画布。顶部约 0–25% 只延续当前画风的背景，可有少量不承担信息的装饰；底部约 83–100% 只延续背景或地面。完整主标题及描边阴影、辅助文案、行动线索、人物面部与手、商品关键细节和表达业务关系的符号，集中在 x≈6–94%、y≈25–82% 的中段，并与边界留出缓冲。行动线索尽量在 y≈78% 以上。上下区域仍属于完整画面，不做白边或缩小的贴片。再说明本方向的标题位置、主体关系和画面动势。

这些百分比是**该次实验的生图构图目标**，固定验收边界仍以[制作规范](production-rules.md)为准。五个业务需求的三轮测试还试过将顶部背景扩至约 0–30%、核心收至 x≈10–90%、y≈32–76% 或 33–78%；标题越过顶部的问题依然多次出现，详见[实验反馈](experiment-findings.md#五个业务需求的三轮安全区测试)。因此把更保守的比例视为待验证候选值，依据每稿的标题长度、主体规模和画风选择留量，成图后逐项验收。生成工具实际输出过 1536×1024，即使输入写了目标 1440×960；提示词可用比例组织画面，验收时按实际尺寸换算。背景可依画风表现为纸纹、天空、色块或场景延续。

## 首轮评估与停点

逐张检查下表，并把具体失败项连同原图交给用户。**首轮完成后停止生成、扩图、覆盖文字与修图，等待用户判断方向和提出修改。**失败项只作为判断信息；如果没有一个方向值得保留，用户可以决定重新探索。此前累积的修订意见不能替代本轮方向判断。

| 关口 | 检查内容 | 首轮表达方式 |
| --- | --- | --- |
| 业务准确 | 指定中文、数字、权益、商品、日期与去向 | 逐项指出错字、伪文字或未经确认的表达 |
| 一眼可读 | 375px 宽下标题先被看到，文字组有充分画面空间，主体解释主张，必要短说明与按钮均可辨 | 标出文字被挤成角标、辅助字太小、按钮缺失、拥挤或焦点冲突的区域 |
| 文案取舍与字形重点 | 业务事实准确，长句已压缩或转到落地页；标题中的数字／关键词有适度设计且清楚可读 | 指出原需求逐字上图、小字无法读、重点字被抹平，或设计干扰识别 |
| 视觉方法与参考边界 | 忽略颜色和文字后，主体造型、场景结构、互动、材质仍能体现参考的画面语言；独特角色、标志及识别性组合已重新设计或替换 | 分别指出“只借配色字体”的表层相似或“具体主体照搬”的过近相似 |
| 创意与密度 | 一个主张、一个主要画面关系；重复权益牌及无解释作用的装饰已取舍 | 指出争夺注意力的元素及可删项 |
| 主体层级 | 一个大主体或紧凑主体组合；其余人物、商品与道具有明显次级关系 | 标出多个同等尺度的大主体挤占文案或安全区的情况 |
| 真人实景质感（如使用） | 手指、肢体、肤质、场景透视、接触阴影、噪点、边缘与光照自然可信 | 标出明显生成感与局部缺陷，不自动返修 |
| 商品印花（如使用） | 图案来源、内容、位置、尺度及同款一致性符合预检与业务素材 | 标出随机图案、文字、标志或不一致之处 |
| 安全与满幅 | 背景铺满；完整文字及描边阴影、面部、商品关键细节位于核心区 | 按实际图片尺寸叠加安全区，记录越界的对象与边界 |
| 主题色 | 选定 C 色号可见，且画面协调 | 记录实际观感与编号 |
| 文件技术 | App 1440×960、不透明 PNG | 记录尺寸或格式问题 |

## 用户选定方向后的修订

用户选定方向并提出反馈后，针对选中方向修订。先把反馈拆成**保留项、改动项、待验项**：保留项写到可观察的造型与构图层面，例如人物轮廓、线条粗细、面部简化程度、填色面积、道具数量与主体比例；改动项写清文案、按钮或位置；待验项保留安全区等尚未通过的检查。修订提示词要同时写入保留项和改动项，并检查改动是否挤占或改写了已认可的主体。用户明确选中旧稿的某一部分时，可以用该旧稿辅助说明**已认可的局部画法**；原始参考图仍提供视觉语言与版权边界，旧稿不自动成为整张新图的画风源。例如只修改左侧文案时，右侧已认可的简笔人物应保持线条、表情、填色和配饰的复杂度。每张完整 Banner 仍只调用一次生图，成图后对照保留项与改动项评估，再交用户判断。

## 安全区控制：单次生图与验收

每张图生成前用[制作规范](production-rules.md)确定标题布局和关键内容可用范围，给完整文字、面部、商品关键细节和行动线索留内部缓冲。提示词说明画面高度中部的内容关系，顶部与底部承载同风格的低信息背景延展；不要把它写成顶部长条留白或底部长条留白。明确排除顶部大标题、底部信息栏和边缘小字。当前每张只调用一次完整生图，不生成分层素材或做受控合成。

成图后按实际尺寸检查边界，记录具体越界对象。若单次生图未满足严格安全区，保持探索稿状态并交用户判断；只有下一次得到用户对该方向的反馈，才可再做一版完整生成。任何不满足边界的稿件不得标作定稿达标。历史受控合成与扩图想法保留在实验记录中，不作为当前用户要求的执行步骤。

## 页面检查与汇报

成图按实际尺寸将 [App 安全区](production-rules.md#关键内容边界app-安全区)等比映射到图片，逐一查看完整标题及描边阴影、面部和商品关键细节；探索稿记录具体越界对象，定稿保留测量结果。再在 375×250 px、100% 页面缩放下查看标题和辅助文案；能接入 V2.1 首页时，另查底部渐变、双入口叠加、展开、滚动与收起。没有真实页面时标注“真实首页待验收”。每个方向汇报主题色编号与 HEX、标题布局、实际文案、创意以及具体未达标项。

用户反馈先记录在 [实验反馈](experiment-findings.md)，并按反馈处理成图。候选方法保留适用条件与待验证状态；经过不同任务的实际成图验证后，再升级为稳定规则。
