# 执行流程：App Banner 生图与评估

本文件负责把[参考图层](reference-analysis.md)和 Banner 层的[创意判断](banner-design.md)、[制作规范](production-rules.md)落实到成图、评估与修订。当前只交付静态 App 素材。探索阶段的完成条件是**按约定数量产出可比较的方向，每个方向各有一张图，问题已标注，用户可以判断方向**；画面未达标本身不触发下一轮生图。

## 首轮生成

默认提出三个有实质差异的方向，每个方向调用生图一次；用户指定数量时按其要求。直接展示 App 图，不以长篇文字方案作为审批关口。每个方向的输入包含：

1. 已核实的业务事实、指定中文和必要的商品、权益。
2. 原始画风参考图与 3–5 个可执行的视觉指纹；标题、主体和背景共享画法。
3. 一句话创意，以及标题与一个大主体或紧凑主体组合如何互相解释。多人出现时，明确谁是主角、谁是明显较小的配角，避免多个同等尺度的大主体并排。
4. 一种标题布局：主标题先被读到，关键内容聚在中央核心，背景和材质延伸至四边。
5. 选定 C 编号与 HEX 在画面中的作用；排除冗余文字、未经证实的业务表达与页面 UI。

提示词要描述阅读顺序、单一主视觉锚点、视觉核心、边缘延展和非关键边缘；有可靠构图参考时可附带。坐标、字号和精确色号仍作为成图后的测量条件。已观察到区域功能写清后可一次得到安全区较好的成图，也观察到后续逐像素返修未必更好；输入中写了数值不等于输出合格。若方案包含生成真人，还要明确自然可信的姿态、肢体和皮肤质感；这只能作为生成目标，实际质量以成图检查为准。

## 区域功能提示词与内部缓冲

按当前画风和信息量组织首轮提示词：先规定**上方和下方的背景功能**，再逐一列出**必须完整留在中段的关键内容**，最后为标题和一个主要主体安排能装进中段的关系。关键内容要比[制作规范](production-rules.md)的验收边界更向内收，给生成偏差留缓冲；标题连同描边阴影、辅助文字、行动线索、面部、手、商品细节和业务关系符号都计入占位。空间不够时先压缩文案或简化主体，再决定各区域的目标比例。

下面是一组白底插画实验使用的功能描述，可按当前画风改写。它曾使“一起团 更便宜”的三张图较好地守住核心区；另一组“低至5.7折”虽视觉聚合，红色标题仍越过规范：

> 画面铺满 3:2 App 画布。顶部约 0–25% 只延续当前画风的背景，可有少量不承担信息的装饰；底部约 83–100% 只延续背景或地面。完整主标题及描边阴影、辅助文案、行动线索、人物面部与手、商品关键细节和表达业务关系的符号，集中在 x≈6–94%、y≈25–82% 的中段，并与边界留出缓冲。行动线索尽量在 y≈78% 以上。上下区域仍属于完整画面，不做白边或缩小的贴片。再说明本方向的标题位置、主体关系和画面动势。

这些百分比是**该次实验的生图构图目标**，固定验收边界仍以[制作规范](production-rules.md)为准。五个业务需求的三轮测试还试过将顶部背景扩至约 0–30%、核心收至 x≈10–90%、y≈32–76% 或 33–78%；标题越过顶部的问题依然多次出现，详见[实验反馈](experiment-findings.md#五个业务需求的三轮安全区测试)。因此把更保守的比例视为待验证候选值，依据每稿的标题长度、主体规模和画风选择留量，成图后逐项验收。生成工具实际输出过 1536×1024，即使输入写了目标 1440×960；提示词可用比例组织画面，验收时按实际尺寸换算。背景可依画风表现为纸纹、天空、色块或场景延续。

## 首轮评估与停点

逐张检查下表，并把具体失败项连同原图交给用户。**首轮完成后停止生成、扩图、覆盖文字与修图，等待用户判断方向和提出修改。**失败项只作为判断信息；如果没有一个方向值得保留，用户可以决定重新探索。此前累积的修订意见不能替代本轮方向判断。

| 关口 | 检查内容 | 首轮表达方式 |
| --- | --- | --- |
| 业务准确 | 指定中文、数字、权益、商品、日期与去向 | 逐项指出错字、伪文字或未经确认的表达 |
| 一眼可读 | 375px 宽下标题先被看到，主体解释主张，辅助字可辨 | 标出太小、拥挤或焦点冲突的区域 |
| 画风同源 | 标题、主体、背景的线条、造型、材质和色彩关系 | 指出哪些元素脱离原始参考 |
| 创意与密度 | 一个主张、一个主要画面关系 | 指出争夺注意力的元素 |
| 主体层级 | 一个大主体或紧凑主体组合；其余人物、商品与道具有明显次级关系 | 标出多个同等尺度的大主体挤占文案或安全区的情况 |
| 真人质感（如使用） | 手指、肢体、比例、皮肤纹理、肤色、噪点、边缘与光照自然可信 | 标出明显生成感与局部缺陷，不自动返修 |
| 安全与满幅 | 背景铺满；完整文字及描边阴影、面部、商品关键细节位于核心区 | 用安全区叠层查看并标出越界位置 |
| 主题色 | 选定 C 色号可见，且画面协调 | 记录实际观感与编号 |
| 文件技术 | App 1440×960、不透明 PNG | 记录尺寸或格式问题 |

## 用户选定方向后的修订

用户选定方向并提出反馈后，针对选中方向修订。生成式修订从**原始业务需求＋原始画风参考图＋用户对该方向的反馈**构建输入；旧生成图不自动成为新的画风源。每次修订后再评估并交给用户判断，迭代次数由用户的反馈决定。

## 安全区控制：从探索到定稿

关键内容区、过渡余量和标题布局的精确边界统一见[制作规范](production-rules.md)。坐标约束属于**确定性验收**，不能仅靠自然语言提示保证。可用三层手段：

1. **探索稿：区域功能＋具体构图。**使用上面的提示结构，让顶部与底部承担背景功能，逐一列出中段关键内容；每个方向说明标题和主体如何占据中段。它已在一组白底手绘实验中得到较好结果，另一组仍有精确越界。首轮逐图检查；越界就标注，不自动重生。
2. **选定方向后的受控合成。**如用户需要稳定达标，将背景、主体、文字作为可定位图层处理：背景铺满 1440×960，主体关键部位放入核心区，文字及描边阴影用可测量边界排版，再按原参考的造型和材质统一。对每个关键图层实际测量边界，留出内部余量，并在 375×250 预览。此法能控制位置和字号，但需制作图层，视觉衔接和手绘字形仍需人工检查。若用户要求全画面和文字一次性生成，须如实告知严格坐标无法保证。
3. **核心区先生成再扩图：待验证实验。**先做中央画面，再向 1440×960 的外围补背景，有利于把原有关键内容置于内部；但生成画幅本身可能把主体裁在边缘，扩图可能改动核心、产生接缝或在外围增添新物件，还需要第二次生成。若试验此法，先确认原中央画面完整；扩展仅处理背景区域，完成后把原核心像素确定性贴回，并检查新边缘没有重要文字、面部和商品细节。只有用户选定方向且需要测试时使用，不能作为探索首轮的自动返修。

区域功能提示在一些画风中可以一次得到较好的安全区表现。需要跨画风、跨多次生成都满足严格边界时，再考虑**图层坐标、边界测量和最终合成**。扩图解决画布延展，无法单独解决核心图内部的标题太大、面部越界或文字错误。

## 页面检查与汇报

在 375×250 px、100% 页面缩放下查看标题和辅助文案；能接入 V2.1 首页时，另查底部渐变、双入口叠加、展开、滚动与收起。没有真实页面时标注“真实首页待验收”。每个方向汇报主题色编号与 HEX、标题布局、实际文案、创意以及具体未达标项。

用户反馈先记录在 [实验反馈](experiment-findings.md)，并按反馈处理成图。经过实际成图验证的通用方法再写入 Skill；未验证的扩图方案保持实验状态。
